# Local Media Downloader

Расширение для Chromium-браузеров, которое разрабатывается с помощью AI-агентов. **Проект в работе: это не завершённый аналог DownloadHelper и не готовый релиз.**

## Что есть в коде

- Manifest V3: service worker, наблюдение за страницей, offscreen host и worker медиадвижка.
- Русскоязычные popup, менеджер заданий и настройки; светлая/тёмная темы и сохранение фокуса.
- Обработка прямых медиафайлов, HLS/DASH, выбор дорожек, субтитры и live-сценарии.
- Локальное хранение OPFS/IndexedDB, remux через Mediabunny и экспорт через Downloads API.
- Запрашиваемые разрешения сайтов, проверки URL/сообщений, обработка сетевых ошибок и отмены.
- Unit-тесты, интеграционные harness, генераторы синтетических медиа и архитектурные эксперименты.

Наличие реализации не означает полную проверку всех форматов и сайтов. Продуктовая архитектура не требует Companion App; FFmpeg/ffprobe используются только разработчиком для тестовых материалов. Обход DRM/ограничений доступа и транскодирование не предусмотрены.

## Сборка

Проверено локально с Node.js 26 и зависимостями lockfile:

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm run build
```

Результат — `dist/`. Устанавливай распакованное расширение через Developer mode → Load unpacked в **отдельном тестовом профиле**, не в личном браузерном профиле.

При публикации прошли typecheck, ESLint, **44 unit-теста** и сборка. Полный интеграционный/browser-прогон при этой публикации не повторялся.

## Что ещё не принято

Остаются интерактивные проверки разрешений сайтов, Save As/отмены/совпадения имён, Reload прерванных заданий и выбора нативных списков клавиатурой. Полная интеграция выпуска, нагрузочная приёмка, независимое review и сравнение с оригинальным расширением не завершены.

`test:integration` требует подготовленных synthetic fixtures, браузеров и инструментов разработчика. Это не команда unit-тестов из чистого клона. `test:e2e` и `package` пока ссылаются на отсутствующие runners. Некоторые экспериментальные скрипты содержат машинно-зависимые пути; просматривай их перед запуском. Большие эксперименты занимают несколько гигабайт.

Тестовые профили, cookies, сгенерированные медиа, результаты испытаний, копии внешних страниц и служебные записи AI-агентов исключены из Git, но сохранены локально. Полный локальный архив приёмки в портфолио-снимок не включён. Для сборки и unit-тестов он не нужен.

## Ветки

`main` — опубликованный WIP baseline, а не стабильный выпуск. `develop` — интеграция. `feature/development` — текущая рабочая ветка от develop. Дальнейшие feature-ветки вливаются в develop через PR. Release/hotfix-ветки создаются при реальной необходимости, а не как пустые заготовки.

Исходно три ветки содержат один снимок. Эта структура не выдаётся за уже пройденный командный Git Flow.
